# 智能问答系统设计：部署与运维

## 1. 本地部署拓扑

docker compose（infra/compose.yaml）拉起基础设施，应用进程跑在宿主机：

| 组件 | 端口 | 部署方式 |
| --- | --- | --- |
| PostgreSQL | 5432 | compose，卷持久化 |
| Redis | 6379 | compose |
| MinIO | 9000 | compose，卷持久化 |
| Ollama | 11434 | 宿主机进程，本机 127.0.0.1 |
| Web（Next.js） | 3000 | pnpm dev:web |
| kb-worker | 无 | pnpm dev:worker |

注意：Ollama 必须绑 127.0.0.1，本机 ::1 上有空库实例的历史坑。

## 2. 启动顺序

1. `pnpm compose:up` 起基础设施。
2. 数据库迁移（prisma migrate deploy）。
3. `pnpm --filter @aichat/web seed` 建种子账号与模型注册表。
4. `pnpm dev:all` 同时拉起 Web 与 Worker。
5. `tsx experiments/demo-seed.mts` 一键预置答辩演示库。

## 3. 可观测性

- Worker 每轮打印 [kb-worker] 前缀的错误日志，租约抢占与续约失败均可观测。
- Document.error 保留最后一次失败原因（截断 1000 字符）。
- 结构化指标（usage log）记录每请求的 token 与耗时，支撑 P95 延迟分析。

## 4. 故障排查速查

| 症状 | 排查 |
| --- | --- |
| 文档一直 PENDING | worker 是否存活；OLLAMA_BASE_URL 是否可达 |
| FAILED/ATTEMPTS_EXHAUSTED | 看 Document.error；非法 UTF-8 或超大文件为永久错误 |
| 检索空结果 | 会话是否绑定 KB；Document.model 与会话嵌入模型是否一致 |
| 引用悬浮空白 | chunk 是否有 headingPath；该文档是否用 structure 策略 |
