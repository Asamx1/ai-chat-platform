# 智能问答系统设计：RAG 检索增强生成管线

## 1. 管线阶段

RAG 管线分为离线索引与在线检索两个半区：

### 1.1 离线索引

1. **解析（parse）**：PDF 走独立 worker 线程的 pdf.js；text/plain 与 text/markdown 直接 UTF-8 解码；统一换行归一化并剔除 NUL。
2. **分块（chunk）**：按 Document.chunkStrategy 调度对应策略（见《分块策略》篇）。
3. **嵌入（embed）**：bge-m3，1024 维，批量 16，服务端不截断（truncate=false）。
4. **入库（storePlan）**：父块先插、子块后插以建立 parentId 引用，全部块携带向量。

### 1.2 在线检索

1. 用户提问 → 查询改写（可选）→ 混合检索。
2. 向量路与词法路各自取 top-20，RRF（k=60）融合。
3. 小顶大（small-to-big）：子块命中后取父块全文作为上下文。
4. 上下文按 4096 字节预算裁剪，最后一个溢出块截断保留。
5. LLM 生成带引用编号的回答，引用绑定 chunkId。

## 2. 上下文预算

默认上下文预算 4096 字节。超出预算时：

- 已满额的块直接丢弃；
- 最后一个放不下的块按 UTF-8 安全边界截断并标记 truncated；
- 截断只发生在块尾部，绝不产生半个汉字。

## 3. 引用机制

每条回答可附带引用列表，包含文档名、块序号、headingPath 与命中片段。
前端在引用徽章上悬浮即可预览 chunk 原文，点击跳转到该文档的分块预览页。

## 4. 指标基线

| 指标 | 目标值 |
| --- | --- |
| 端到端首包延迟 | ≤ 5s（本地 qwen3） |
| 检索 top-5 命中率 | ≥ 80%（60 QA 集） |
| 单文档索引耗时 | ≤ 20s（400 行 Markdown） |
