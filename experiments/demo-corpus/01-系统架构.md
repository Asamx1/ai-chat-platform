# 智能问答系统设计：系统架构

## 1. 总体架构

智能问答平台采用前后端分离的多进程架构，核心进程包括：

- **Web 应用（apps/web）**：Next.js 全栈应用，承载登录、知识库管理、对话与引用展示。
- **知识库 Worker（apps/worker/kb-worker）**：独立进程轮询 Document 队列，执行解析、分块与向量化。
- **PostgreSQL**：业务数据 + pgvector 向量索引 + tsvector 全文索引的统一存储。
- **MinIO**：对象存储，保存上传文档的原始字节流。
- **Ollama**：本地推理服务，提供 bge-m3 嵌入与本地对话模型。

## 2. 数据流

上传一篇文档的完整生命周期：

1. 用户在 Web 界面上传文件，Web 校验 MIME 与大小后写入 MinIO。
2. Web 在事务中创建 KnowledgeBase（如新建）与 Document 记录，状态置为 PENDING。
3. kb-worker 通过 `FOR UPDATE SKIP LOCKED` 抢占租约，将状态置为 PROCESSING。
4. Worker 从 MinIO 读取字节流，解析为纯文本，按 chunkStrategy 分块。
5. 调用 Ollama `/api/embed` 批量生成 1024 维向量（每批 16 条）。
6. storePlan 在事务中写入 Chunk（含 headingPath、父子关系）并把 Document 置为 READY。

## 3. 关键设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 队列实现 | Postgres 租约而非独立 MQ | 降低部署复杂度，租约超时自动恢复 |
| 向量库 | pgvector 而非专用向量库 | 与业务库同事务，一致性免费 |
| 嵌入服务 | 本地 Ollama bge-m3 | 数据不出域，答辩环境可离线 |
| 对象存储 | MinIO（S3 兼容） | 私有桶 + 服务端读取，无预签名 URL 泄露面 |

## 4. 容错与恢复

- 失败重试：attempt < 3 的 FAILED/PENDING 文档可被重新抢占；达到 3 次置为 FAILED 终态。
- 租约心跳：Worker 每 10 秒续约 30 秒租约，续约失败立即中止当前任务。
- 永久错误（PermanentRagError，如非法 UTF-8、超大文件）不重试，直接失败并记录原因。
