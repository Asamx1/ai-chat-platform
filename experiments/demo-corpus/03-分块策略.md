# 智能问答系统设计：分块策略

## 1. 三种策略

系统实现了三种可切换的分块策略，写入 Document.chunkStrategy 字段：

| 策略 | 原理 | 适用场景 |
| --- | --- | --- |
| fixed | 定长滑动窗口（默认 512 字符、重叠 50） | 纯文本、无结构 |
| recursive | 按 Markdown 标题层级递归下探再定长切分 | 结构较弱的文档 |
| structure | 标题路径感知 + 父子双层分块（默认） | 手册、设计文档 |

## 2. structure 策略细节

structure 是生产默认策略，其核心是**父子双层结构**：

- **父块（PARENT）**：以二级标题（##）为边界聚合整节内容，供生成阶段提供完整上下文。
- **子块（CHILD）**：在父块内部再切小块（目标 256 字符），供嵌入与检索精确命中。
- **headingPath**：每个块记录从根标题到当前标题的 JSON 路径，如 `["RAG 检索增强生成管线","在线检索"]`，用于前端过滤与引用展示。

检索时命中的是子块，喂给 LLM 的是对应父块全文——这即“小顶大”扩展。

## 3. 策略选择实验结论

在 60 QA 中文语料上的对照实验（M9）结论：

- structure 的 top-5 命中率 78%，recursive 71%，fixed 63%。
- structure 在“跨小节细节题”上优势最大，因为 headingPath 保留了语义边界。
- fixed 在无结构纯文本上仍是最稳的选择，structure 的收益以结构存在为前提。

## 4. 边界处理

- 代码块与表格视为原子单元，不在中间切断。
- 空标题节合并入上一节，不产生空 headingPath。
- 分块器保证 offset 按 Unicode 码点计数，与前端预览的字符高亮一致。
