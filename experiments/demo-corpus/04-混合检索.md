# 智能问答系统设计：混合检索与重排

## 1. 为什么要混合

纯向量检索对术语精确匹配弱（如型号 “qwen3:0.6b”、错误码 “EMBED_TIMEOUT”），
纯 BM25 对同义改写弱（“怎么找回密码” vs “重置登录凭证”）。混合两者取长补短。

## 2. 融合流程

1. **向量路**：bge-m3 余弦相似度，pgvector 取 top-20。
2. **词法路**：tsvector + GIN 索引的 BM25 近似（k1=1.5, b=0.75），top-20。
3. **RRF 融合**：score = Σ 1/(k + rank)，k=60，融合后截 top-20。
4. **MMR 多样性重排**：λ=0.5，输出 top-5。

中文分词采用字符 bigram，拉丁文本按词切分，与 pg `simple` 配置行为对齐。

## 3. 实验数据（M9 混合臂）

| 策略 | 纯向量 top-5 | 混合检索 top-5 |
| --- | --- | --- |
| structure | 78% | 87% |
| recursive | 71% | 81% |
| fixed | 63% | 74% |

三个策略在混合检索下全部提升 9-11 个百分点，说明提升来自检索层而非分块层。

## 4. 权限过滤

检索 SQL 在同一查询内联完成权限判定：KB 属主 = 会话属主 = 当前用户，
且 Document 状态为 READY、model 与会话嵌入模型一致。未授权的块不进入融合阶段，
避免“先检索后过滤”导致的 top-k 空洞。
