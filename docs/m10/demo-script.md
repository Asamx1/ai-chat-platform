# M10 答辩演示脚本：10 问演示线

语料：答辩演示库（8 篇《智能问答系统设计》中文文档，structure 策略）。
加载：`pnpm exec tsx experiments/demo-seed.mts`（幂等，重跑即重置）。
叙事线：简单事实查找 → 结构/引用展示 → 跨节综合 → 对比与决策题。

| # | 问题 | 预期答案摘要 | 展示点 | 讲解要点 |
|---|------|-------------|--------|----------|
| 1 | 系统里一共有哪几种分块策略？分别适合什么场景？ | fixed/recursive/structure 三种及各自适用场景 | 基础检索命中 | 开场热身：单跳事实题，任何策略都能答对，先建立"它能用"的信任 |
| 2 | 默认的上下文预算是多少字节？超出预算怎么处理？ | 4096 字节；满块丢弃、末块按 UTF-8 边界截断 | 引用徽章 + 悬浮预览 | 悬浮展示 chunk 原文与 headingPath，强调"答案可溯源到块" |
| 3 | structure 策略的父子双层结构是怎么工作的？ | 子块检索、父块喂给 LLM（小顶大），headingPath 记录标题路径 | headingPath 结构感知 | 指着悬浮里的 headingPath 讲"检索命中叶子、上下文给整节" |
| 4 | 上传的文档支持哪些格式？大小限制是多少？ | text/plain、text/markdown、application/pdf；20MB / 200 万字符 | 简单多事实召回 | 一个问题召回两个并列事实，展示单轮多块拼装 |
| 5 | 部署这套系统需要启动哪些组件？分别跑在哪个端口？ | PG 5432 / Redis 6379 / MinIO 9000 / Ollama 11434 / Web 3000 | 表格类文档检索 | 表格作为原子块不被切断，整表召回是 structure 的功劳 |
| 6 | 为什么必须做混合检索？纯向量检索有什么短板？ | 术语精确匹配弱（型号、错误码）；RRF+MMR 取长补短 | 跨节综合（04 篇） | 从"是什么"进阶到"为什么"：跨小节综合题 |
| 7 | 混合检索对三种分块策略分别带来了多少提升？ | 78→87 / 71→81 / 63→74，全部 +9~11 点 | 数据表格 + 对比 | 强调提升来自检索层而非分块层——单一变量实验纪律 |
| 8 | 一篇文档从上传到可被检索，中间经历了哪些步骤？ | MinIO → Document(PENDING) → 租约抢占 → 解析/分块/嵌入 → storePlan → READY | 跨文档全链路（01+02 篇） | 两个文档各出一块引用，展示跨文档拼装与引用列表 |
| 9 | 评估体系是怎么保证不同实验之间可比的？ | 固定 60 QA、冻结判分协议、单一变量差异、双格式结果入库 | 评估方法学（05 篇） | 答辩高频追问点：先讲纪律再讲数字 |
| 10 | 如果下一步要接入重排模型，应该放在管线哪个位置？为什么？ | RRF 之后、MMR 之前；先融合召回再精排多样性 | 开放推理 + 路线图 | 压轴题：模型需要综合 04 与 08 篇做推理，展示 RAG 的决策支持能力 |

## 演示操作提示

- Q1-Q4 用默认检索即可；讲 Q7 前可打开 KB 分块预览页对比 structure/fixed 的 headingPath 差异。
- Q2/Q3 演示引用悬浮：鼠标停在引用徽章上 1-2 秒再念出 headingPath。
- 每题后可顺手点击引用徽章跳到块预览页，再返回对话（浏览器返回即可）。
- 备用兜底：若现场网络/服务异常，按 docs/m10 录屏顺序口述 + 截图讲解。
