## 0. 目标与决策原则

本方案首先建立可信的检索和回答评测，再分别验证语义切分、Wiki 编译、一跳实体图是否带来收益。只有通过质量、引用、延迟和成本验收的能力才进入默认检索链路。

保留以下方向：

- 原文是事实依据；Wiki 与实体图是可重建的派生产物。
- 编译期的问答候选生成、摘要和实体抽取采用 DeepSeek API；具体模型标识与参数必须记录。
- Wiki 与原文共用 KB，可共用向量存储，但检索必须能区分并独立关闭派生层。
- 本期图检索只做一跳，不实现社区检测、社区摘要或多跳推理。
- 评测、版本化基础设施、semantic、Wiki、图扩展分阶段交付；实验失败可以保留关闭状态，不要求所有能力上线。

本文规定设计契约和验收条件，不直接执行迁移、重建或部署。实施任务应按项目现有工作台流程登记、运行和验证；检查通过后进入 `awaiting_review`，经明确的人类或指定审阅者验收后才能记为 accepted。

| 模块 | 已确认现状 | 对本方案的影响 |
|---|---|---|

## 2. 阶段 A：建立可重复的评测基线

### 2.1 评测集

首批由 DeepSeek 从原始 SOURCE 文档生成 20–50 条候选，由用户人工审核问题、参考答案及证据。该规模用于初始回归，不作为证明小幅提升的充分统计依据。

候选生成只使用原文，不使用待评测的 Wiki 或实体图。人工补充真实查询，覆盖：直接事实、长文局部事实、表格/数字、实体歧义、关系证据、跨文档综合、时效/冲突、无法回答的问题。

建议模型字段：

| 字段 | 含义 |
|---|---|
| `id / kbId / question` | 用例身份与问题 |
| `referenceAnswer` | 人工审核后的参考答案；无答案题注明应拒答 |
| `evidenceGroups` | 必须覆盖的证据组；组内允许等价证据，跨组表示多项必要事实 |
| `evidenceAnchors` | 文档 ID、源版本、规范化文本位置、证据文本及其哈希 |
| `questionType / answerable` | 问题分层与可回答性 |
| `origin` | `LLM_GENERATED` 或 `HUMAN_AUTHORED` |
| `reviewStatus` | `DRAFT / APPROVED / REJECTED`，与 origin 分开 |
| `split` | 开发集或保留测试集 |
| `reviewedAt / createdAt` | 审核及创建时间 |

将批准用例按问题类型分层划分为约 70% 开发集、30% 保留集；题量不足时披露每类样本数。调参只查看开发集，保留集用于阶段评审；若据其结果继续调参，应补充新的保留题。

### 2.2 指标与计算口径

- `DocumentHitRate@5`：前 5 个检索单元是否来自任一正确文档，仅作粗粒度辅助指标。
- `EvidenceHitRate@5`：前 5 个检索单元能否提供至少一组有效证据。
- `EvidenceCoverage@5`：必要证据组中被前 5 个检索单元覆盖的比例，适用于多事实问题。
- `EvidenceMRR@5`：首个有效证据单元的倒数排名，未命中记 0。
- 答案正确性、引用有效性、无答案题的正确拒答率：通过固定回答链路和人工复核评估；LLM 评分只作辅助。
- 检索 P50/P95、超时率、降级率、上下文 token 数，以及编译成本、重试成本和耗时。

检索指标同时报告“扩展前候选”和“最终上下文证据覆盖”。固定最终上下文 token 预算，避免通过无限回源或扩展父块获得不公平优势。Wiki 自身命中不自动算证据命中，必须解析到有效原文并验证证据覆盖。源版本和规范化规则固定时，可用证据 span 覆盖率进行定位匹配；仅哈希相等不适用于不同切分边界，语义等价证据需人工标注。

每份运行报告记录：代码 commit、语料快照、评测集版本、索引 generation、策略及开关、embedding/LLM 模型、prompt 版本、参数、随机性设置、运行时间与硬件/并发环境。

### 2.3 验收原则

冻结 baseline 后逐题比较胜出、退化和不变案例；同时披露置信区间或样本量限制。小样本上的“没有下降”不等于已证明非劣。

硬门槛包括：引用可解析且指向正确源版本、无越权检索、关闭派生层后不残留其候选、关键回归题不退化。质量允许退化的边界、成本上限与延迟目标在实验开始前写入评测配置，不根据结果事后放宽。未显式配置成本预算时不得启动批量编译。

## 3. 阶段 B：版本、引用与派生产物生命周期

此阶段先于 Wiki、图扩展和全量重建。

### 3.1 三类版本

- `SourceVersion`：原文内容哈希、不可变源对象、规范化文本及解析器/规范化版本。解析规则改变也产生新的源表示版本。
- `IndexGeneration`：针对固定语料快照生成的一组 chunk、embedding、Wiki 和图记录，附完整配置快照。
- `CompileJob`：记录源版本、目标 generation、产物类型、模型、prompt/schema 版本、状态与重试信息。

所有引用至少包含 `sourceDocumentId + sourceVersionId + start/end + evidenceTextHash`。位置按该版本规范化文本的 Unicode code point 计算，与当前切分 offset 语义保持一致。当前 generation 的 chunk ID 是加速定位字段，ordinal 仅用于版本内显示和定位。

### 3.2 构建与激活

新 generation 先在后台构建，在线继续读取旧 active generation。新版本完成数量核对、引用校验和必要检查后，在事务中切换 KB 的 active generation 指针。请求开始时捕获 generation，后续召回、图路和回源使用同一版本。

chunk 的唯一约束需从 `(documentId, ordinal)` 调整为包含 generation 的约束；所有召回及父块查找同步限定 generation。迁移时将现有 chunk 归入首个 generation，不能直接复用当前“删除旧 chunk 再写入”的模式实现可回滚重建。

旧 generation 在回滚窗口及在途请求结束前保留。回滚通过切回仍有效的旧 generation 完成；不通过重新计算旧结果伪装即时回滚。回滚不能恢复已删除或已撤权的源内容。

### 3.3 更新、删除和撤权

源更新后创建新版本，对应派生产物重编译；旧派生结果不得与新源 chunk 混用。源删除或撤权后立即阻断检索，包含旧 generation；之后异步清理引用、事实和产物。

跨文档实体页按事实记录依赖关系。删除一个来源时移除该来源贡献并重新编译页面，其他有效来源可以保留；没有有效来源的事实不得继续用于回答。不能只靠页级 `sourceDocumentId` 表示多源依赖。

## 4. 阶段 C：semantic 切分实验

### 4.1 接口策略

保留现有纯同步策略，新增 worker 使用的异步规划入口，例如 `planChunksAsync(input, strategy, config, context)`。其中 context 提供 embedding 服务、AbortSignal 与模型信息；旧策略通过适配器直接返回现有结果，semantic 执行异步嵌入。worker 必须 await 规划结果，并继续遵守租约失效取消规则。

涉及 registry、策略类型、入口导出、worker、参数校验和测试，不能仅新增一个策略文件。

### 4.2 切分规则

1. 按标题和结构边界提取单元；中英文句子单独分段，保留原文位置映射。
2. 表格、列表、代码块采用结构规则处理。超长表格按行组切分并保留表头关联；超长代码按行/结构分组，不按自然语言句子嵌入判断边界。
3. 对可参与语义判断的单元分批嵌入，按相邻单元或固定邻域相似度寻找候选边界；算法及邻域大小写入配置。
4. `semanticThreshold=0.75` 仅作为开发集调参起点，不宣称适用于全部语料。配置必须是有限数，参数含义明确为余弦相似度阈值。
5. 打包器优先保留语义边界，同时满足 child/parent 长度和 overlap 约束；不得在后续 pack 阶段无条件跨越已确认的边界。
6. 保持现有 ChunkResult 的 kind、parent、headingPath 和原文 offset 语义，并验证覆盖、顺序与父子关系。

### 4.3 失败和可观测性

可恢复的语义嵌入失败允许回退 structure；记录 `requestedStrategy`、`effectiveStrategy`、原因、耗时和配置版本。取消、租约丢失和无效配置不得吞掉并继续写入。

评测报告单独列出降级样本，不将其计为 semantic 成功案例。句子嵌入与最终 chunk 嵌入分别统计成本和耗时；缓存键包含文本哈希及 embedding 模型版本。

## 5. 阶段 D：Wiki 编译层

### 5.1 存储和任务边界

Document 增加 `kind=SOURCE | WIKI_SUMMARY | WIKI_ENTITY`。派生正文保存为不可变 Markdown 对象，提供真实 `objectKey`、`mime=text/markdown` 和字节大小，不伪造必填字段；元数据记录 generation 和编译版本。

只有 SOURCE 文档触发编译与 SOURCE rebuild。派生 Document 由编译任务负责索引，普通文档领取查询显式排除派生类型，防止重复处理或递归生成 Wiki。

源索引成功事务同时写入 outbox 事件，消费者幂等创建 CompileJob。SOURCE READY 只表示原文可检索，编译状态单独展示；进程在 READY 后崩溃也不能丢失编译任务。

任务状态：`PENDING → RUNNING → SUCCEEDED / FAILED / CANCELLED`。幂等键包含源版本、generation、产物类型及编译配置哈希；租约和 attempt 防止旧任务写回覆盖新任务。失败可重试但有次数上限，重复事件不能产生重复产物。

### 5.2 内容契约

- 摘要页：300–500 字为默认展示目标；关键事实列表单列，每项事实必须关联原文证据。长文允许按章节组织，不强迫全部事实压缩进固定字数。
- 实体页：每个 canonical entity 在一个 generation 内形成一个页面，汇总可访问的有效来源；不按每篇文档重复创建同名实体页。
- 实体互链：保存实体 ID 作为机器可解析目标，`[[名称]]` 仅作为展示语法，避免同名链接歧义。
- 事实校验：检查引用存在、版本正确、证据确实支持主张；类型和 JSON 格式正确不代表事实正确。
- 文档正文视为不可信数据，不能借正文中的指令改变抽取任务、调用工具或扩大发送范围。

### 5.3 冲突处理

保留双方主张、证据、来源时间及适用条件，标记为“待核实冲突”。条件不同、时间不同或产品版本不同不能仅凭文字相反判成矛盾。冲突识别不自动裁定真假，也不覆盖已有来源。

### 5.4 检索、回源和开关

同库存储不意味着无条件混排。所有检索路径都根据请求配置过滤 Document.kind，包括向量、词法、纯向量回退、父块扩展和回源。

- `RAG_WIKI=false`：候选及上下文只允许 SOURCE，关闭编译不是检索回滚的替代品。
- 开启时按来源分配候选额度并进行同源去重，避免原文、摘要、实体页挤占全部 top-k。
- Wiki 命中后，仅按相关事实取必要原文证据；最多使用剩余上下文预算，不无限展开所有 provenance。
- 回源失败、来源失效或越权时移除该事实；无法验证的摘要不得作为已证实的事实进入回答。

默认候选配额、融合权重与回源上限作为实验参数冻结，经过开发集校准后才用于保留集。

## 6. 阶段 E：Ontology 实体图

### 6.1 实体与 schema

采用独立 canonical entity ID。名称、别名、类型、上下文和来源用于实体匹配，不以 `(kbId, name, type)` 唯一约束强制合并。

每 KB 的 ontology 配置必须版本化，包含实体类型、关系类型、关系方向、允许的主客体类型和必要的时间/条件限定。配置变更影响抽取时建立新 generation，避免新旧 schema 混合解释。

### 6.2 建议数据模型职责

| 模型 | 职责与必要约束 |
|---|---|
| Entity | KB 范围内的稳定实体身份；同名可以并存 |
| EntityAlias | 实体别名和标准化名称；别名冲突不强制唯一归属 |
| EntityMention | generation、实体、chunk 与源证据关联；外键及组合唯一约束 |
| EntityRelation | 主体、谓词、客体、时间/条件、schema 版本；按事实语义去重 |
| RelationEvidence | 一条关系的多个来源证据，支持独立删除和追溯 |
| DerivedFact | Wiki 与实体页使用的事实及多源依赖，可引用已验证的关系事实 |

所有关系补齐 Prisma relation 的双向定义、外键、删除行为与查询索引。写入时确保实体、关系、证据属于同一 KB 与目标 generation；涉及复合约束的部分以迁移 SQL 落实。常用索引覆盖 KB/generation、主体/谓词、客体、实体 mention 与别名查找。

### 6.3 抽取与消歧

在 chunk 级抽取，prompt 注入版本化 schema；随后执行类型、方向、证据和主客体范围校验。名称标准化只用于召回候选，实体是否合并由上下文证据决定；低置信度时保留多个候选，不强行合并。

实体页由已验证的实体/事实记录渲染，避免 Wiki 和图分别抽取出两套互不一致的实体身份。Wiki 只启用摘要时不依赖完整图；实体页功能在实体身份与事实层完成后上线。

### 6.4 一跳检索

1. 在当前会话可访问 KB 中，用 query 词法匹配名称/别名，保留歧义候选；不在查询期新增 LLM 调用。
2. 读取一跳关系，并优先返回支持关系本身的 RelationEvidence；邻居 mentions 仅作为补充候选。
3. 对关系类型、方向、有效时间和权限过滤，再形成图路排序；排序规则及 tie-break 必须固定。
4. 对 chunk 去重后以独立权重参与融合；图路不默认与其他路等权，参数由消融实验决定。

初始保护上限建议为：每题最多 5 个实体候选、每实体 10 条关系、图路最多 30 个 chunk、独立预算不超过 300ms。上述是待压测的工程初值，不是已验证性能结论；实际预算还必须小于请求剩余时间。

`Promise.allSettled` 仅负责收集结果，不提供超时。应用层 deadline 与数据库 statement timeout 配合，超时不阻塞已有检索；有能力时取消底层查询。记录图路超时、错误和降级原因，用户无需等待失败图路，但运维与评测不能静默丢失这些信息。

## 7. 批量重建、成本与上线控制

### 7.1 重建操作

`POST /api/kb/[id]/rebuild` 仅提交后台任务，鉴权后固定 SOURCE 版本快照，返回 job ID。支持进度、取消、失败清单、重试、幂等与恢复，不在 HTTP 请求内完成重建。

区分 `rechunk`、`recompile` 与完整 `rebuild`：只改摘要 prompt 时复用当前源索引；只有切分或 embedding 配置改变才重算相应索引。新 generation 构建阶段旧 generation 持续服务。

先小批量试跑，再逐步扩大；只在目标 generation 完整通过发布检查后激活。若允许部分文档失败，必须明确产物覆盖范围并单独评审，不把“其余文档成功”报告成“全部成功”。

### 7.2 编译成本账本

新增与 CompileJob 关联的编译调用记录，避免强行为后台编译创建聊天 OrchestrationRun。复用供应商调用封装与价格计算工具，但新账本独立记录：模型、操作类型、输入/输出 token、价格版本、费用、attempt、状态、耗时和请求去重标识。

批次必须有明确费用或 token 上限、并发上限与最大重试次数。调用前预留预算，完成后结算；预算不足进入暂停状态。供应商实际 usage 未返回时记为未知，不记为免费；网络超时后的重复请求可能重复计费，报告需披露。

报告区分问答候选生成、语义嵌入、摘要、实体抽取与重试成本。单文档成本除均值外报告分布，避免长文异常被平均值掩盖。

### 7.3 开关与回滚

| 控制项 | 关闭后的保证 |
|---|---|
| `RAG_WIKI` | 所有召回/回退/回源路径排除 Wiki 候选 |
| `RAG_GRAPH` | 不运行图路，不使用图扩展候选 |
| semantic 构建策略 | 阻止新 semantic 构建；不会自动改变已有索引 |
| active generation | 原子切换已验证的旧索引，实现切分和派生产物版本回滚 |
| 编译开关 | 停止新编译任务；已发布产物是否检索由检索开关控制 |

KB 实验配置与环境默认值的优先级必须统一：环境总开关关闭时，KB 配置不能重新开启；请求记录实际生效配置。禁止仅在 UI 中隐藏功能却保留后台召回。

## 9. 实施顺序与验收

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| A：评测 | 初始批准题、开发/保留划分、baseline、配置快照 | 人工证据审核完成，指标可重复计算 |
| B：版本基础 | 稳定引用、generation、依赖与激活/回滚 | 重切分后引用不误指；删除/撤权不泄漏；旧索引可恢复 |
| C：semantic 实验 | 异步规划、结构单元、降级记录 | offset/父子关系/取消检查通过；独立对比给出收益或关闭结论 |
| D1：摘要 Wiki | 独立编译任务、来源校验、检索过滤 | 幂等及恢复通过；关闭后零 Wiki 候选；独立质量报告 |
| E1：实体事实层 | 实体身份、关系证据、schema 版本 | 同名歧义、多来源、删除及权限检查通过 |
| D2/E2：实体页与图路 | 实体页、一跳检索、预算和降级 | 关系证据正确，图路超时不拖垮主链路 |
| F：组合与重建 | 小批试跑、消融结果、预算、激活与回滚 | 组合有可解释收益；报告完整；明确审阅接受后再默认启用 |

各阶段可独立停止或保持关闭。semantic 与 Wiki/图的实验均使用同一固定语料与评测版本，不能以语料变化冒充算法收益。

### 9.1 消融矩阵

至少比较：baseline、仅 semantic、仅摘要 Wiki、仅图路；再比较有收益的组合。实体页作为独立子能力记录，不能在“仅图路”条件中暗中启用 Wiki 页面召回。

若 semantic 退化，后续 Wiki/图实验继续使用原切分策略。冻结模型、上下文预算和其他检索参数，避免同时改变多个变量。报告按问题类型拆分，列出全部退化题及成本变化。

### 9.2 必须覆盖的验证场景

- 重新切分导致 chunk ID/ordinal 改变后，证据仍指向正确源版本。
- 新 generation 构建失败或被取消，旧 generation 持续可用且无混读。
- 删除/撤权后，原文、摘要、实体页、图证据及旧 generation 均不可绕过访问限制。
- READY 提交后进程崩溃、outbox 重放、任务重复领取和租约丢失均不造成丢任务或重复发布。
- 同名不同实体不误合并，一条关系多个证据来源可独立删除。
- Wiki/图总开关关闭后，包括纯向量回退在内均不返回关闭层内容。
- 图查询超时、回源超时和 embedding 取消按预算终止或降级，记录真实原因。
- 预算耗尽停止新增调用，暂停后恢复不重复发布已成功产物。
- 表格、代码、中英文混排、超长单元的切分位置及父子覆盖保持有效。

除针对上述行为的测试外，执行相关现有测试和受影响包的类型检查。测试通过与线上质量提升分别报告，不互相替代。

## 10. 研究依据与适用边界

研究用于提出实验假设，不直接保证本项目获得相同比例收益。

- [OG-RAG：Microsoft Research](https://www.microsoft.com/en-us/research/publication/og-rag-ontology-grounded-retrieval-augmented-generation-for-large-language-models/?lang=ja)：其公开方法采用 ontology-grounded 超图及专门检索算法；文中报告的事实召回和回答正确率收益依赖实验设置，不能外推为本方案一跳图扩展的预期提升。本方案不以“轻量 schema 必然有效”作为已证实前提。
- [WiCER，arXiv:2605.07068](https://arxiv.org/abs/2605.07068)：展示了特定实验条件下盲目编译的事实丢失与质量失败，并通过诊断和迭代编译改进。该结论支持保留原文、逐事实回源及评测闭环；不将论文中的失败比例描述为所有 Wiki 系统的通用概率。
- [OMD-GraphRAG，arXiv:2603.25152](https://arxiv.org/abs/2603.25152)：作为 schema 引导抽取与双通道融合的研究参考；本期未复现其完整聚类及检索流程。
- [DEG-RAG，arXiv:2510.14271](https://arxiv.org/abs/2510.14271)：区分实体消歧与三元组反思过滤。大小写/别名归一化仅是预处理，不能等同于论文完整降噪方法。

原方案中的 Karpathy LLM Wiki 及社区解读暂作为概念背景；本修订版不以未核验的 gist 地址、star 数或“社区共识”支持关键工程决策。正式补入时应提供直接原始链接、版本日期和对应论述。
