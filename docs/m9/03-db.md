# M9 数据库增量变更设计

任务：T-20260921-10661074。本文仅为设计：不修改实际 schema、不创建迁移文件、不执行迁移。后续实现以本文 SQL 为迁移依据。

## 1. 基线与字段语义

已阅读 `packages/db/prisma/schema.prisma`、`packages/rag/src/chunk.ts`，并核对现有 RAG 迁移、`store.ts`、`retrieve.ts` 与 `docs/m9/00-grill-report.md`。

- 当前 `chunk()` 默认窗口 512、重叠 50；偏移量是规范化并以换行拼接后的 Unicode code point 索引，`end` 为开区间。新增策略继续遵守此偏移语义。
- 当前 `Chunk.embedding` 为必填 `Unsupported("vector(1024)")`；保留维度、类型、非空约束、已有值及向量查询。不重算已有 embedding，不新增 ANN 索引；pgvector 已存在。
- `Chunk.parentId String?`：指向同表父块；旧块和根块为 NULL。父块删除时子块 `parentId` 置 NULL；文档删除继续沿用原有级联删除所有块。
- `Chunk.headingPath String?`：可选标题路径，例如 `安装 / Linux / 配置`；无标题或旧块为 NULL。由分块器生成，仅供展示和归因，不作为唯一键或权限依据。
- `Document.chunkStrategy String? @default("fixed")`：记录实际成功落库的分块策略。缺省插入为 `fixed`，显式 NULL 仍允许；读取时 NULL 按 `fixed` 解释。候选策略标识为 `fixed`、`recursive`、`structure`，由应用注册表校验，不加数据库枚举或 CHECK。
- `Chunk.searchVector Unsupported("tsvector")?`：数据库自动生成的全文检索列，DDL 不加 NOT NULL；表达式对 NULL 文本使用空串，因此正常生成结果非 NULL，空文本生成空向量。应用不写入此列。

本任务明确要求数据库默认 `fixed`，优先于审问报告 Q5 的“默认结构感知”。以后应用若默认选择结构感知，应在成功重切割的同一事务中显式写入 `structure`，不能改变历史文档的含义。

## 3. 迁移 SQL 全文

前提：现有迁移已应用，连接 `search_path` 指向现有业务表所在 schema；数据库支持 stored generated columns（PostgreSQL 12+）。本迁移只执行一次，由迁移历史跟踪，不用 `IF NOT EXISTS` 隐藏结构差异。SQL 不包含扩展安装、旧列变更或数据删除。

```sql
BEGIN;

-- 事务局部设置；获取锁超时即失败，不修改全局配置。
SET LOCAL lock_timeout = '5s';
SET LOCAL statement_timeout = '10min';

ALTER TABLE "Document"
  ADD COLUMN "chunkStrategy" TEXT DEFAULT 'fixed';

ALTER TABLE "Chunk"
  ADD COLUMN "parentId" TEXT,
  ADD COLUMN "headingPath" TEXT,
  ADD COLUMN "searchVector" tsvector
    GENERATED ALWAYS AS (
      to_tsvector('pg_catalog.simple'::regconfig, coalesce("text", ''))
    ) STORED;

ALTER TABLE "Chunk"
  ADD CONSTRAINT "Chunk_parentId_fkey"
  FOREIGN KEY ("parentId") REFERENCES "Chunk"("id")
  ON DELETE SET NULL ON UPDATE CASCADE;

CREATE INDEX "Chunk_parentId_idx" ON "Chunk" ("parentId");
CREATE INDEX "Chunk_searchVector_idx"
  ON "Chunk" USING GIN ("searchVector" tsvector_ops);

COMMIT;
```

新增 stored 生成列会计算存量行并产生表重写、WAL 和额外存储；建索引也会扫描表。此版本选择维护窗口内的原子事务，普通 CREATE INDEX 不是并发构建，整个事务持有 DDL 锁，不能宣称无停机。后续执行前需评估 Chunk 表大小、磁盘余量和锁等待，暂停摄取并安排维护窗口；超时后回滚事务、排查再重试。大表需要另行设计分阶段迁移，不能直接把本事务内索引改成 CONCURRENTLY。

## 4. 中文全文检索与索引

固定使用 `pg_catalog.simple`，避免依赖连接的 `default_text_search_config`。生成列仅索引 `text`，不拼接标题路径，便于独立比较正文的词法召回；查询也显式使用同一配置。stored 生成列配合 GIN 是 PostgreSQL 支持的实现方式。[PostgreSQL：Tables and Indexes](https://www.postgresql.org/docs/current/textsearch-tables.html)

`simple` 不等于中文分词器。默认 parser 按字符类别和边界切分，受数据库 locale 影响；连续中文可能整体成为 token，短词不保证匹配含该词的长句，全文检索也不是子串搜索。必须在目标数据库用下节 SQL 观察实际 token，并用中文 QA 集评估召回；中文仍依靠现有 1024 维向量召回，词法无命中时保留向量结果。[PostgreSQL：Parsers](https://www.postgresql.org/docs/current/textsearch-parsers.html)

本期不引入 zhparser：避免新增服务端扩展及分词词库的部署、版本和维护依赖，维持已有 pgvector 环境即可运行的迁移范围。GIN 只能加速已有 token 的匹配，不能弥补中文分词能力。本期也不添加隐式预分词；以后若引入分词，需同时设计文档与查询的统一处理以及全文向量重建。

## 5. 现有数据与应用兼容性

| 对象 | 迁移后行为 |
| --- | --- |
| 旧 Document | `chunkStrategy` 读为 `fixed`；不改变状态、租约、计数和 `updatedAt`，不自动重切割 |
| 旧 Chunk | `parentId`、`headingPath` 为 NULL，`searchVector` 自动由既有正文生成 |
| 旧写入路径 | `store.ts` 显式列举 INSERT 列，省略新增列仍有效；生成列由数据库维护 |
| 旧检索路径 | `retrieve.ts` 只读取既有字段，向量距离、1024 维转换和权限过滤继续有效 |
| 原有唯一约束 | 保留 `(documentId, ordinal)`；父块和子块共用文档内 ordinal 空间，不能各自从 0 编号 |
| 新父块 | 同样必须提供合法 1024 维 embedding；本设计不允许无向量父块，不放宽原列约束 |

自引用外键只保证父块存在，不能保证同一文档或无环。后续应用必须校验父子 `documentId` 相同、禁止自引用和环；M9 采用父/子两层时还应确保父块自身无父节点。先插父块、再插子块，或先全部以 NULL 插入后在同一事务中绑定。`parentId` 索引用于子块查找及父块删除时的外键处理。

重切割继续复用现有文档租约和事务：锁定文档、删旧块、写新块、更新计数与实际 `chunkStrategy`、标记 READY 必须原子完成。旧 worker 不会更新策略字段；因此结构化写入启用前必须完成所有摄取 worker 升级，不能让旧 worker 重切割非 fixed 文档，造成策略标签与实际内容不一致。`chunkCount` 继续表示实际落库 Chunk 行数，包含父块。

全文候选、父块展开均须保留现有查询中的知识库所有者、会话所有者、会话绑定、READY 状态与 embedding model 条件。父块展开额外限制同一 `documentId`，不能仅凭 `parentId` 读取其他文档。

## 6. 发布与仅 env 回滚

以下 env 名称是供后续实现遵循的约定，当前源码尚未实现，不能将本文视为开关已可用：

| 建议开关 | 关闭时行为 |
| --- | --- |
| `RAG_STRUCTURE_ENABLED=false` | 新摄取/重切割强制 fixed；成功写入时记录 fixed |
| `RAG_PARENT_EXPANSION_ENABLED=false` | 不展开父块，直接返回检索块 |
| `RAG_HYBRID_ENABLED=false` | 跳过全文检索与融合，使用现有向量查询 |
| `RAG_RERANK_ENABLED=false` | 若后续已接入，跳过重排 |
| `RAG_MULTIQUERY_ENABLED=false` | 若后续已接入，使用原查询 |
| `RAG_HYDE_ENABLED=false` | 若后续已接入，停用 HyDE |

先应用增量迁移，再上线能正确维护策略和处理 NULL 的代码，最后启用相应功能。回滚只关闭上述开关并让 web/worker 重新加载 env，保留 schema、迁移历史、新列、数据和索引；不 DROP、不执行 down migration、不回退 schema 或 Prisma Client。

已存结构化块继续可用，不自动还原成 512/50 的历史块。关闭父块展开后可继续用向量检索所有已存块，排序可能包含父块和子块；env 回滚恢复基础处理路径，不保证恢复迁移前完全相同的结果。若需旧切分结果，可之后按 fixed 走正常重切割流程，不是回滚前置步骤。关闭 hybrid 也不会停止生成列维护或释放索引空间，不能用 env 消除 DDL 锁或数据库存储成本。

## 7. 验证 SQL（供后续执行，本任务未运行）

以下均为只读 SQL。表名解析前提与迁移相同；查询返回的异常数量应为 0。正式启用前还需由后续实现测试生成列随正文 UPDATE 更新、父块删除置 NULL、文档级联删除及 env 回退；本文不执行数据写入测试。

```sql
-- A. 环境、新增列可空性、默认值与生成表达式。
SELECT version(), current_schema(), current_setting('lc_ctype');
SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';
SELECT table_name, column_name, data_type, udt_name,
       is_nullable, column_default, is_generated, generation_expression
FROM information_schema.columns
WHERE table_schema = current_schema()
  AND ((table_name = 'Document' AND column_name = 'chunkStrategy')
    OR (table_name = 'Chunk'
        AND column_name IN ('parentId', 'headingPath', 'searchVector')))
ORDER BY table_name, column_name;
-- 预期 4 行均可空；策略默认 fixed；searchVector 为 tsvector、ALWAYS。

-- B. 向量类型和原非空约束：预期 vector(1024)、true。
SELECT format_type(a.atttypid, a.atttypmod) AS embedding_type,
       a.attnotnull
FROM pg_attribute a
WHERE a.attrelid = '"Chunk"'::regclass
  AND a.attname = 'embedding' AND NOT a.attisdropped;
SELECT count(*) AS bad_vector_dimensions
FROM "Chunk" WHERE vector_dims(embedding) <> 1024;

-- C. 自引用外键、GIN/B-tree 索引定义和有效性。
SELECT conname, convalidated, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid = '"Chunk"'::regclass
  AND conname = 'Chunk_parentId_fkey';
SELECT i.relname, x.indisvalid, x.indisready, pg_get_indexdef(i.oid)
FROM pg_index x JOIN pg_class i ON i.oid = x.indexrelid
WHERE x.indrelid = '"Chunk"'::regclass
  AND i.relname IN ('Chunk_parentId_idx', 'Chunk_searchVector_idx');
-- 预期 FK 已验证，ON DELETE SET NULL / ON UPDATE CASCADE；两索引有效。

-- D. 存量兼容与生成值一致性。
SELECT coalesce("chunkStrategy", 'fixed') AS effective_strategy, count(*)
FROM "Document" GROUP BY 1;
SELECT count(*) AS chunks,
       count(*) FILTER (WHERE "parentId" IS NOT NULL) AS linked_chunks,
       count(*) FILTER (WHERE "headingPath" IS NOT NULL) AS headed_chunks
FROM "Chunk";
-- 在尚未启用新写入时：有效策略仅 fixed；linked/headed 均 0。
SELECT count(*) AS bad_search_vectors FROM "Chunk"
WHERE "searchVector" IS DISTINCT FROM
      to_tsvector('pg_catalog.simple'::regconfig, coalesce("text", ''));
SELECT count(*) AS bad_parent_links
FROM "Chunk" c LEFT JOIN "Chunk" p ON p.id = c."parentId"
WHERE c."parentId" IS NOT NULL
  AND (p.id IS NULL OR c.id = p.id OR c."documentId" <> p."documentId");
-- 两层模型中，父块有父节点即异常，也覆盖环导致的异常。
SELECT count(*) AS non_root_parents
FROM "Chunk" c JOIN "Chunk" p ON p.id = c."parentId"
WHERE p."parentId" IS NOT NULL;

-- E. 在实际 locale 下观察中文分词和子串匹配限制。
SELECT alias, token, lexemes
FROM ts_debug('pg_catalog.simple'::regconfig,
              '数据库检索 数据库 检索 PostgreSQL');
SELECT to_tsvector('pg_catalog.simple'::regconfig, '数据库检索') AS lexemes,
       to_tsvector('pg_catalog.simple'::regconfig, '数据库检索')
       @@ plainto_tsquery('pg_catalog.simple'::regconfig, '数据库') AS short_match;
-- short_match 是待观察的召回限制，不将 true 作为通过条件。

-- F. 只检查计划，不执行扫描；小表选择 Seq Scan 不代表索引失效。
EXPLAIN (COSTS ON)
SELECT id FROM "Chunk"
WHERE "searchVector" @@ plainto_tsquery('pg_catalog.simple'::regconfig, '数据库');
-- 此查询仅用于数据库维护验证；产品查询必须添加第 5 节的权限/状态过滤。
```
